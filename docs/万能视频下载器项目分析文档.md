## 1. 项目概览

**万能视频下载器** 是一个轻量级的多平台视频下载工具，支持：

- **视频解析**：粘贴 URL 即可获取视频标题、封面、时长、作者、平台来源等元数据
- **视频下载**：基于 yt-dlp 库，支持 1700+ 平台（B站、YouTube、抖音、Twitter 等）
- **AI 视频总结**：通过阿里云百炼大模型提取字幕并生成文本总结、思维导图、智能问答
- **订阅系统**：预留免费/月付/年付三档套餐

项目采用 **前后端分离** 的单体架构，后端为 Python FastAPI，前端为 Next.js 16（React 19 + TypeScript + Tailwind CSS v4）。

### 关键架构决策

1. **内存存储**：所有任务状态存储在 Python 字典中（`self.tasks`），服务重启后丢失。`requirements.txt` 中有 `redis` 依赖但未接入。
2. **线程池并发**：下载操作在 `ThreadPoolExecutor(max_workers=3)` 中执行，避免阻塞异步主循环。
3. **SSE 动态输出**：下载进度通过轮询每 0.5s 推送；AI 总结使用真正的 SSE 事件流。
4. **单例模式**：`VideoDownloader` 和 `VideoSummarizer` 均为模块级单例。
5. **Next.js 代理**：前端 `/api/*` 请求通过 `next.config.ts` rewrite 代理到后端 `localhost:8000`。SSE 流式请求绕过代理直连后端，以避免缓冲导致流式效果丢失。

### 5.2 API 路由

#### 5.2.1 下载端点 (`/api/download`) — `app/api/download.py`

| 方法 | 路径 | 功能描述 |
|------|------|---------|
| `POST` | `/api/download` | 创建下载任务，立即返回 `task_id`，异步启动下载 |
| `GET` | `/api/download/status/{task_id}` | 轮询查询任务状态（进度、速度、ETA） |
| `GET` | `/api/download/progress/{task_id}` | SSE 流式推送下载进度（每 0.5s 推送一次，直到 `finished`/`failed`） |
| `GET` | `/api/download/file/{task_id}` | 下载已完成的视频文件（`FileResponse`，`video/mp4`） |

**SSE 进度推送逻辑：**
```
while True:
    task = downloader.get_task(task_id)
    yield {"event": "progress", "data": progress_json}
    if task.status in [FINISHED, FAILED]:
        yield {"event": "done", "data": progress_json}
        break
    await asyncio.sleep(0.5)
```

#### 5.2.2 解析端点 (`/api/parse`) — `app/api/parse.py`

| 方法 | 路径 | 功能描述 |
|------|------|---------|
| `POST` | `/api/parse` | 提交视频 URL 进行元数据解析（标题、封面、时长、作者、平台） |
| `GET` | `/api/parse/{task_id}` | 轮询获取解析结果 |

**解析流程：**
1. 创建任务 → `TaskStatus.PENDING`
2. 异步调用 `downloader.parse_video(url, task_id)` → `TaskStatus.PARSING`
3. yt-dlp 提取信息（不下载视频） → `TaskStatus.PARSED`
4. 缩略图下载为 base64（绕过防盗链）
5. 播放列表检测并提取前 50 个条目
6. 平台识别：bilibili、youtube、twitter/x、tiktok、douyin、微博、西瓜视频

#### 5.2.3 AI 总结端点 (`/api/summarize`) — `app/api/summarize.py`

| 方法 | 路径 | 功能描述 |
|------|------|---------|
| `POST` | `/api/summarize` | 创建总结任务（异步执行，轮询获取结果） |
| `POST` | `/api/summarize/stream` | **SSE 流式总结**（主流用法）：顺序输出字幕提取状态 → 文本流 → 脑图 |
| `GET` | `/api/summarize/{task_id}` | 获取总结结果（文本+脑图+字幕） |
| `POST` | `/api/summarize/chat` | AI 对话问答（基于视频字幕内容） |

**SSE 流式总结的完整事件流：**
```
1. type: "status"   → "正在提取字幕..."
2. type: "status"   → "正在生成AI总结..." + subtitle_with_timestamps
3. type: "chunk"    → 文本增量（多个，逐个字符输出）
4. type: "done"     → 完成标记 + 完整文本
5. type: "mindmap"  → 脑图 JSON 数据（异步生成，在 done 之后）
```

**下载方法的关键设计：**

```python
async def download(self, url, task_id, quality, subtitles, translate):
    # 1. 构建 yt-dlp 格式参数（优先 H.264/AVC 兼容 QuickTime）
    if quality == "best":
        format_spec = "(bestvideo[height<=720][vcodec~='avc']/...) +bestaudio/best"
    else:
        format_spec = "(bestvideo[height<={N}][vcodec~='avc']/...) +bestaudio/best"

    # 2. 进度回调钩子（更新内存中的 task 状态）
    def progress_hook(d):
        if d['status'] == 'downloading':   # 更新进度/速度/ETA
        elif d['status'] == 'finished':     # 标记完成

    # 3. yt-dlp 配置
    ydl_opts = {
        'format': format_spec,
        'outtmpl': f'{downloads_dir}/{task_id}.%(ext)s',
        'merge_output_format': 'mp4',
        'noplaylist': True,
        'cookiesfrombrowser': ('chrome', None, None, None),  # 从 Chrome 提取 cookies
    }

    # 4. 在线程池中执行同步下载
    info = await loop.run_in_executor(download_executor, sync_download)
```

**解析方法的设计要点：**
- 使用 `extract_info(url, download=False)` 只获取信息不下载

- 提取前 50 个视频条目
- 缩略图转为 base64 以绕过 B站等平台的防盗链限制

| `generate_text_summary_stream` | `(text: str) -> AsyncGenerator` | 流式文本总结 |
| `generate_mindmap` | `(text: str) -> Dict` | 生成思维导图 JSON |
| `chat` | `(text, question, history) -> Dict` | AI 对话问答 |

**字幕提取语言优先级：**
```
1. ai-zh（AI 字幕，中文）    — 优先
2. zh-Hans（简体中文）
3. zh-Hant（繁体中文）
4. en（英文）
5. ja（日文）
6. ko（韩文）
```

**字幕数据获取优先级：**
1. `info['subtitles']` → 人工字幕
2. `info['automatic_captions']` → 自动生成字幕
3. 字幕文件（SRT）→ 本地已下载文件
4. 直接 data 字段 → URL 下载

**AI 调用模型：** `qwen-max`（阿里云百炼）

**Prompt 设计：**
- **文本总结**：8000 字符截断 → `一句话概括 + 3-5点核心要点 + 适合人群`
- **脑图生成**：8000 字符截断 → 严格的 JSON 树形结构 `{"root": "...", "children": [...]}`
- **AI 对话**：8000 字符截断 → 3 轮历史上下文 + 用户问题

**流式输出的实现：**
```python
# 使用 threading + queue 在异步和同步之间桥接
def sync_stream():
    responses = Generation.call(stream=True, incremental_output=True)
    for response in responses:
        chunk_queue.put(response.output.text)
    chunk_queue.put(None)  # 结束标记

thread = threading.Thread(target=sync_stream, daemon=True)
thread.start()

while True:
    chunk = await loop.run_in_executor(None, chunk_queue.get)
    if chunk is None: break
    yield chunk
```

**流程：**
```
用户点击"下载视频" → POST /api/download
```

### 7.3 AI 视频总结

**完整流程：**
```
用户点击"AI 总结" → POST http://localhost:8000/api/summarize/stream
→ SSE 事件流：

1. type:"status" → "正在提取字幕..."
  └─ yt-dlp 提取字幕（skip_download=True, writesubtitles=True）
  └─ 语言顺序: ai-zh → zh-Hans → zh-Hant → en
  └─ SRT 格式解析（去时间轴和序号，提取纯文本）

2. type:"status" → "正在生成AI总结..."
  └─ 字幕文本截断至 8000 字符
  └─ 构建 prompt: "一句话概括 + 3-5个要点 + 适合人群"

3. type:"chunk" × N → 文本流式输出（阿里云百炼 qwen-max, incremental_output=True）
  └─ 前端打字机效果展示（每 30ms 显示 5 字符）

4. type:"done" → 文本总结完成

5. type:"mindmap" → 脑图 JSON 数据（异步生成，不阻塞文本展示）
  └─ 调用 qwen-max, result_format='message'
  └─ 生成 JSON 树形结构
  └─ 前端 MindMapViewer 渲染
```

**AI 对话（Chat）：**
```
用户在 ChatPanel 输入问题 → POST /api/summarize/chat
→ 后端调用 VideoSummarizer.chat()
  → 构建 prompt: 视频字幕 + 最近3轮对话 + 用户问题
  → 调用 qwen-max 生成回答
  → 更新对话历史
→ 前端显示回答
```

**字幕内容预处理：**
```python
# SRT 格式解析
if '-->' in content:
    for line in content.split('\n'):
        if '-->' in line: continue      # 跳过时间轴
        if line.isdigit(): continue      # 跳过序号
        text_lines.append(line)
    return ' '.join(text_lines)          # 连接为纯文本
```

## 11. 现有问题与优化建议

### 11.1 安全隐患

| 问题 | 严重程度 | 说明 |
|------|---------|------|
| SECRET_KEY 默认值 | 🔴 高 | `config.py` 中硬编码 `"your-secret-key-change-in-production"`，若部署到生产环境会导致 JWT 可被伪造 |
| CORS 全开放 | 🟡 中 | `allow_origins=["*"]` 在生产环境不安全 |
| 无请求速率限制 | 🟡 中 | 无任何 rate limiting，易被滥用 |
| 无输入校验 | 🟡 中 | URL 输入无白名单/黑名单验证 |
| 无用户认证 | 🟡 中 | 任何人都可以使用所有功能 |

### 11.2 代码质量

| 问题 | 说明 |
|------|------|
| 下载完成后文件未清理 | `downloads/` 目录会无限增长，无自动清理机制 |
| 总结任务的字典无锁 | `summarize_tasks` 在 summarize.py 中无线程安全保护 |
| 两个任务存储不统一 | `downloader.tasks` 和 `summary_tasks` 是独立的，架构不清晰 |
